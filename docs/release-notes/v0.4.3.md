The first release with a real feature story since 0.4.0. Rust and C# get
docking — which they could not do at all before — macOS gets native menus and
app-owned window chrome, and a use-after-free class in the language bindings is
closed.

0.4.1 and 0.4.2 were single-fix releases cut one commit apart; everything below
has landed since.

Still alpha: features, APIs, and the set of supported platforms are all in
flux. Verified on Linux (Ubuntu, x86-64), macOS (Apple Silicon), and Windows
(x86-64).

> **The C ABI is now version 5** (0.4.2 shipped 2). It is an exact-match check,
> so a binding built against an older core refuses to load rather than
> misbehaving. Rebuild anything that links `affineui_c` directly; the published
> Rust, C#, and Python packages already match.

### Docking in Rust and C#

**Rust and C# can now build dockable apps.** This was not a gap in those
bindings — `affineui_c` exposed 52 view functions and *zero* dock functions, so
there was nothing to bind to. What C# did ship was a `DockPanelAt()` *accessor*,
which reads an existing panel's active tab — enough to make the API look present
while being unable to create a single panel. Python was unaffected: it binds
C++ `View` directly.

The C ABI now carries the whole surface — the dock container, the center pane,
placed dockables, per-pane tab toolbars, and the four providers (size,
active-tab, placement, layout) — mirroring the C++ and Python shape. Drag-to-dock
and tearoff persistence work without marshalling a recursive layout tree across
the boundary. (#119, #121)

**Pane sizes can be saved, not just restored.** `Document::dock_pane_sizes()`
is now exposed in all three bindings:

```rust
let sizes = app.document().dock_pane_sizes();   // Vec<(String, i32)>
```
```csharp
var sizes = app.Document.DockPaneSizes();       // IReadOnlyList<(string, int)>
```
```python
sizes = app.document().dock_pane_sizes()        # list[tuple[str, int]]
```

Apps could already feed sizes *in* through `set_dock_size_provider`, but had no
way to read them back *out* — so a user's splitter drags were unpersistable and
`on_layout_changed` was a dead-end callback that told you the layout had changed
with no way to learn the new sizes. `dock_overrides()` did not cover it: that
records only *structure* (where a panel was dragged or torn off to), never size.

It reads the live flex-basis, so it reflects splitter drags. The flexible
center/document pane has no fixed basis and is omitted. (#128, #129)

### Native macOS menus and window chrome

**`App::set_menu()` builds a real `NSMenu`** from a platform-neutral model
shaped like Electron's `Menu.buildFromTemplate` — roles, accelerators
(`"CmdOrCtrl+S"`), checkboxes, icons, accent swatches. Custom-drawn rows carry
their content as *data*, so each maps to a genuine `NSMenuItem` affordance
rather than an `NSView` escape hatch or a second render path. (#61)

**`App::on_close_request(cb)` is a single veto point.** Return `false` to
cancel. The window button, Cmd-Q, the menu's Quit, `App::close()`, and an
app-drawn close button all route through it, so save-on-exit cannot be bypassed
by picking a different exit. `App::quit()` remains the uncancellable form. (#60)

**`Config::titlebar`** (`Hidden` / `HiddenInset` / `Frameless`, named as in
Electron) drops the system title bar while keeping the window resizable and
snappable. The engine publishes only *facts* to CSS — the measured
window-button band as `--affineui-titlebar-inset-*` / `--affineui-titlebar-area-*`
(the web's `env(titlebar-area-*)`, which we publish on macOS too, where Electron
leaves apps to hardcode ~80px) — plus `data-affineui-platform` and the
inheriting `--affineui-app-region` drag hook. No pixels, no color: Decius binds
those vars to its title area, and an app whose title strip is its own thing
binds them in its own stylesheet. (#62)

The vendored `sokol_app.h` menu patch is **gone, and nothing replaced it**. It
turns out no patch was needed: `sapp_macos_get_window()` already exists and the
init callback runs from inside `applicationDidFinishLaunching`, so `NSApp` and
the `NSWindow` both exist by the time the app layer starts. The macOS shell now
lives in `src/platform/macos/`, outside the vendored tree. (#126)

**macOS is the platform implemented this cycle.** Windows and Linux take the
same `Config`, the same menu model, and the same CSS — the platform layer
no-ops, the vars read `0px`, and the drawn menubar stays as it was. A title bar
written against these vars today is already correct when the chrome work lands
on those platforms. Nothing regresses in the meantime.

See [`docs/WINDOW_CHROME_AND_MENUS.md`](../WINDOW_CHROME_AND_MENUS.md).

### Fixes

**Callback `View` wrappers could outlive the View they borrowed.** Rust `View`
is cloneable, and C#/Python callback wrappers can be stored — and they retained
a borrowed native `View*` after the callback returned. Once the framework-owned
View was destroyed, a later call from a safe language dereferenced freed memory.

Callback Views now resolve through a generation-checked weak token immediately
before each operation. Retaining one is no longer a use-after-free; expired
objects fail through the language's ordinary error mechanism instead —
`ObjectDisposedException` in C#, a catchable panic in Rust, `ReferenceError` in
Python, with `IsAlive` / `is_alive()` / truthiness to test first. Measured
overhead is ~0.9 ns per operation in Rust and ~2.7 ns in C#. (#127)

**`affineui_document_dock_pane_size_at` reported success with a null id.**
`dup_string()` can fail on OOM; the function returned 1 anyway, handing a
binding a null pane id it would persist under an empty key. It now fails and
writes nothing. The same guard was applied to its sibling
`affineui_document_dock_override_at`. (#129)

### Release tooling

**A final release now ships an RC's exact binaries.** `Publish a release` runs
no compiler: it re-stamps the tested pre-release's metadata, copies every
compiled member byte-for-byte, and refuses to publish if a single byte moved.
The pre-release suffix never reaches the compiler, so an RC's binaries and the
release's are bit-identical by construction.

This is paid for by the 0.4.x series: we published four times in one day, and
twice a fix verified on one platform shipped a regression on another that no
build had ever exercised.

**One action, one outcome.** `Cut release` used to push a tag and then dispatch
two *separate* workflow runs — it went green before anything was published, and
you had to hunt down the other runs to learn whether the release happened.
There are now two self-contained actions: **Build a pre-release** (green =
built, tested, published to every pre-release channel, tagged) and **Publish a
release** (green = live on PyPI, crates.io, and nuget.org, tagged). A `v*` tag
existing is proof that version worked.

**The version lives in the repo, not the workflow.** You type the number; the
workflow verifies it against the committed manifests and refuses otherwise.
Every version bug in this series came from a number stamped in at build time
from a source nobody reviewed. (#109, #125)

See [`docs/RELEASING.md`](../RELEASING.md).

### Testing

- The C ABI's dock pane-size readback is now covered from C++, not only through
  the bindings. Both Rust and C# read sizes through those functions, so a
  regression there breaks persistence in every language at once — while the C++
  suite, the one that runs on all three platforms, stays green. (#130)
- CI builds `affineui_c` (the shared C ABI both Rust and C# link) and runs the
  Python, Rust, and C# suites, the C# docking and lifetime checks, and every
  example. Previously no job built the examples or the shared C ABI at all.

### Notes

Pane sizes are recovered by matching the literal `flex:0 0 <N>px` in a pane's
style attribute. Every writer emits that exact form today, so it is correct —
but it is a formatting-sensitive coupling rather than a parsed one, and a
routine CSS tidy-up would silently yield an empty list rather than an error.
#130 now fails loudly if that happens.
